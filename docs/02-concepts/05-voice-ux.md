# 음성 UX 원칙: 귀로 듣는 답은 달라야 한다

## 1. 다섯 가지 원칙

| 원칙 | 왜 | Nunchi에서 |
|---|---|---|
| **첫 문장에 결론** | 귀는 앞부분만 기억하고, 다 듣기 전에 움직임 | 시스템 프롬프트 1번 규칙 |
| **짧게 (1~3문장, 120자)** | 듣는 시간 = 기다리는 시간 | `max_tokens=384`, 프롬프트 |
| **기호 금지** | TTS가 "별표 별표"라고 읽거나 멈춤 | 마크다운·이모지·[1] 제거 후 읽기 |
| **숫자는 읽기 쉽게** | "14:00"보다 "오후 2시" | 프롬프트 5번 규칙 |
| **모르면 모른다고** | 틀린 확신은 현장에서 위험 | "문서에는 없지만…" 규칙, strict 모드 |

## 2. 기다림을 줄이는 기술

1. **모델 상주**(`keep_alive=30m`) + 서버 시작 시 예열 → 첫 질문도 빠르게
2. **STT와 LLM에 같은 모델** → 모델 교체 대기 없음
3. **문장 단위 스트리밍** → 첫 문장이 완성되는 즉시 읽기 시작
4. **폰 TTS** → 네트워크 왕복 없이 바로 소리
5. **긴 문장 자르기** → 80자 넘으면 쉼표에서 나눠 합성 (일부 TTS 모델의 긴 문장 잘림 방지)

## 3. 호출 방법 (트리거)

"헤이 메타"는 Meta AI가 받습니다. 내 앱을 부르는 방법은:

| 방법 | 장점 | 단점 |
|---|---|---|
| 앱의 큰 마이크 버튼 (기본) | 확실함 | 폰을 꺼내야 함 |
| 블루투스 리모컨/셔터 버튼 | 손 안 쓰기 쉬움 | 기기 필요 |
| DAT Voice Invocations: "헤이 메타, ○○ 시작해" | 완전 핸즈프리 | 실험 기능, Developer Center 승인 필요 |
| DAT Inputs: 안경 캡처 버튼 이벤트 | 안경만으로 | 실험 기능 |

## 4. 확인·실패 응답

- 말을 못 알아들으면: "잘 못 들었어요. 다시 한 번 말씀해 주세요." (짧고, 다음 행동을 알려 줌)
- 허브 연결 실패: "허브에 연결하지 못했어요." → 화면에는 원인(주소·토큰)을 자세히
- 위험 질문(부상·화재·중독): 안전 행동과 119를 먼저

## 5. 대화 기억

최근 3턴을 기억해서 "그럼 주말엔?" 같은 후속 질문을 이해합니다. 세션은 30분 동안 말이 없으면 잊고, 앱의 **초기화** 버튼으로 바로 지울 수 있어요.

## 6. 화면이 있을 때와 없을 때

같은 질문이라도 화면(웹·폰 앱)으로 볼 땐 조금 더 자세한 답이 좋습니다. `style`을 `voice`(기본)·`text`로 바꿀 수 있어요. `text`는 목록과 인용 번호([1])를 허용합니다.
